:toc:

== Monitoring

Use the Kafka Connect REST API to monitor the connector and its task.
In PostgreSQL, track `confirmed_flush_lsn`, `restart_lsn`, and the amount of retained WAL.
On each worker, monitor CPU, JVM memory, and free space in `optimized.transaction.spill.directory`.

== Troubleshooting

. Save the task status and its log.
. Check the worker's connections to PostgreSQL and Kafka.
. Confirm that the slot uses `pgoutput` and belongs to the intended database.
. Check publication availability, user privileges, and access to the transaction spill directory.
. After fixing the issue, verify that events flow again and the slot position advances.

[IMPORTANT]
====
Keep the replication slot and Kafka Connect source offsets when restarting. Dropping the slot can make the required WAL position unavailable.
====
